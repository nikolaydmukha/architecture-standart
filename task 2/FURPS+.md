| Код  | Требования                                                                                                                                                       | Комментарий                                                                                                                                        |
|------|------------------------------------------------------------------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------|
| F    | **Функциональные (Functionality)**                                                                                                                               |                                                                                                                                                    |
| F-01 | На сайте клиент должен иметь возможность просматривать список доступных депозитных продуктов и актуальные процентные ставки                                      | Необходимо обеспечить отображение актуальной информации о депозитах для новых клиентов                                                             |
| F-02 | На сайте клиент должен иметь возможность оставить заявку на депозит, указав ФИО и номер телефона                                                                 | Заявка должна передаваться в систему кол-центра для дальнейшей обработки менеджером                                                                |
| F-03 | Менеджер кол-центра должен иметь возможность просматривать заявки с сайта, связываться с клиентами и предлагать особые условия                                   | Используется существующая система кол-центра                                                                                                       |
| F-04 | Новый клиент, подавший заявку через сайт, должен пройти идентификацию в отделении банка до открытия депозита                                                     | Требование обусловлено необходимостью личной проверки документов нового клиента                                                                    |
| F-05 | В интернет-банке клиент должен иметь возможность просматривать доступные депозитные продукты, актуальные и уникальные(конкретно для него) процентные ставки      | Персонализированные ставки должны предоставляться с учётом данных клиента                                                                          |
| F-06 | В интернет-банке клиент должен иметь возможность выбрать счёт, указать сумму и подать заявку на открытие депозита                                                | Основной цифровой сценарий для действующих клиентов банка                                                                                          |
| F-07 | Подача заявки в интернет-банке должна подтверждаться одноразовым смс-кодом                                                                                       | Подтверждение рекомендуется реализовать отдельным компонентом(без доработки ядра интернет-банка подрядчиком)                                       |
| F-08 | Сотрудник депозитного бэк-офиса должен иметь возможность просматривать и обрабатывать заявки на открытие депозитов, подтверждать условия депозита и ставку в АБС | В рамках MVP обработка заявок выполняется сотрудником, а не автоматически                                                                          |
| F-09 | Система должна отправлять клиенту смс после подтверждения ставки и после открытия депозита                                                                       | Необходимо предусмотреть два отдельных события для отправки уведомлений                                                                            |
| F-10 | Сотрудники депозитного и кредитного бэк-офисов должны иметь возможность работать с единым актуальным справочником депозитных ставок                              | Сейчас ставки хранятся в XLS-файлах. Необходимо централизованное хранение информации                                                               |
| F-11 | Система должна сохранять историю заявок, изменений условий и решений сотрудников                                                                                 | Дополнительное требование для аудита, контроля действий сотрудников и разбора спорных ситуаций                                                     |
| U    | **Удобство использования (Usability)**                                                                                                                           |                                                                                                                                                    |
| U-01 | Интерфейсы сайта и интернет-банка должны соответствовать корпоративной дизайн-системе банка                                                                      | Необходимо использовать утверждённые цвета, логотип и единые принципы оформления                                                                   |
| U-02 | Процесс подачи заявки должен быть понятным и содержать минимальное количество действий со стороны клиента                                                        |                                                                                                                                                    |
| U-03 | Клиент должен получать понятную обратную связь о результате каждого этапа обработки заявки                                                                       | Пример: заявка принята, ожидает обработки, ставка подтверждена, депозит открыт                                                                     |
| U-04 | Интерфейс должен корректно отображаться на распространённых устройствах и размерах экранов                                                                       | Дополнительное требование для удобства работы с сайтом и интернет-банком с мобильных устройств и компьютеров                                       |
| R    | **Надёжность (Reliability)**                                                                                                                                     |                                                                                                                                                    |
| R-01 | Доступность интернет-банка и новых сервисов открытия депозитов должна составлять не менее 99,9%                                                                  | Архитектурное требование бизнеса.                                                                                                                  |
| R-02 | Система должна сохранять работоспособность при отказе основного ЦОД за счёт переключения на резервный ЦОД                                                        | Сейчас интернет-банк работает в одном ЦОД. Необходимо предусмотреть отказоустойчивую инфраструктуру                                                |
| R-03 | Заявки и результаты их обработки не должны теряться при временной недоступности интегрируемых систем                                                             | Дополнительное требование. Рекомендуется использовать надёжную асинхронную передачу сообщений и механизм повторной обработки                       |
| R-04 | Повторная отправка одного запроса не должна приводить к созданию дублирующих заявок или повторному открытию депозита                                             | Дополнительное требование. Необходимо предусмотреть идемпотентность операций                                                                       |
| R-05 | При сбоях отправки смс система должна обеспечивать повторную отправку уведомлений и регистрацию ошибок                                                           | Позволяет избежать потери важных уведомлений клиенту                                                                                               |
| P    | **Производительность (Performance)**                                                                                                                             |                                                                                                                                                    |
| P-01 | Время отклика пользовательских операций должно быть минимальным                                                                                                  | Конкретные показатели необходимо согласовать с бизнесом и проверить нагрузочным тестированием                                                      |
| P-02 | Загрузка справочных данных, включая депозитные продукты и ставки, не должна занимать более 1 секунды в штатном режиме                                            | Учитывает существующую проблему интернет-банка с медленной загрузкой справочной информации                                                         |
| P-03 | Новые сервисы должны поддерживать горизонтальное масштабирование при увеличении количества пользователей и заявок                                                | Позволяет увеличивать производительность добавлением экземпляров приложений и распределением нагрузки                                              |
| P-04 | Новые цифровые каналы не должны создавать критическую дополнительную нагрузку на базу данных АБС                                                                 | База АБС уже перегружена. Необходимо минимизировать синхронные запросы                                                                             |
| P-05 | Система должна обеспечивать распределение пользовательских запросов между серверами приложений и ЦОД                                                             | Необходимо для горизонтального масштабирования и повышения устойчивости интернет-банка                                                             |
| S    | **Поддерживаемость (Supportability)**                                                                                                                            |                                                                                                                                                    |
| S-01 | При разработке новых компонентов необходимо преимущественно использовать технологии, уже применяемые в банке                                                     | Учитываются существующие компетенции и технологический стек: .NET, Java, React, MS SQL и Oracle                                                    |
| S-02 | Новые технологии должны быть совместимы с существующими платформами разработки и эксплуатации                                                                    | Необходимо учитывать текущую платформу интернет-банка: ASP.NET MVC 4.5 и .NET Framework 4.5                                                        |
| S-03 | Для новых интеграций с использованием очередей сообщений предпочтительно применять Apache Kafka                                                                  | Kafka выбрана как перспективная технология. Из-за несовместимости текущей версии интернет-банка потребуется промежуточный интеграционный компонент |
| S-04 | Архитектура новых компонентов должна предусматривать возможность дальнейшего расширения и перехода к микросервисной модели                                       |                                                                                                                                                    |
| S-05 | Для новых компонентов и интеграций должна быть подготовлена техническая документация                                                                             | Документация должна включать описание API, форматов сообщений, схем данных, обработки ошибок и развертывания                                       |
